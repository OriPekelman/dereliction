Give your pixels mass.

Leave this page alone for five seconds. Every pixel becomes a particle, every word a rigid body, and the paper pours over the letters like sand. Scroll, and it puts itself back together.

Open the playground Read the code

What it is

A single script, no build step, no server. It renders the viewport to pixels in the browser, hands a million of them to a WebGL2 simulation, and gives the text to a rigid-body engine. Gravity can apply to dark pixels only. Wind can blow away everything that is not text. Letters can fall into a pile. Sand can pour over them for as long as you like.

It is meant to happen to an ordinary page: after a while without any activity, the page you were reading comes apart; the first scroll or key press brings it back, and the page is an ordinary page again.

Use it

<script src="physical-web.js" defer></script>
<script>
  PhysicalWeb.attach({ idle: 8000, preset: 'Avalanche' });
</script>

Tell it what should hold and what should go, in your own stylesheet:

header   { --physics: solid; }   /* never moves; sand piles on it   */
.card    { --physics: rigid; }   /* one body, falls as a block      */
.fine    { --physics: sand;  }   /* its text is loose grains        */

This italic line is marked sand. It will not survive the avalanche; it goes with the paper.

Presets

Letter pileevery glyph is its own body
Hourglassan endless trickle of sand through a narrow spout, onto the text
Sandstormwind on everything that is not text; lightness becomes depth
Ink fallsonly the dark pixels get gravity; the light ones are viscous
Meltgravity on everything, drag by lightness
Reassemblea critically damped spring back to the page

Under the hood

Two renders of the page, one with the text made transparent, are diffed into a pixel-exact ink mask. Particle state lives in float textures; one fragment shader is the physics step. Bodies come from matter.js and are rasterised every frame into an obstacle map, which is what the sand piles on. Chrome, Firefox and Safari 15+, anything with WebGL2.

Prefer pixel-perfect captures? A build-time prerender or a small Playwright service are included too. Neither is required.
